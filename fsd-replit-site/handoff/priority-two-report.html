  • The seven existing clothing banners retain their approved layout, imagery, typography, titles, navigation and line membership. Existing men's series and women's approved logo mappings were not reassigned.
  • New Wearable Technology, Strength Equipment, Combat Equipment and Performance Accessories banners use the same established black/gold banner and product-card classes.

  • Catalogue collection identifiers now take priority over conflicting legacy product names. Specific collection/series/tag metadata is preferred, while records without a specific assignment retain compatible legacy matching. Generic Core metadata does not erase existing line membership.
  • The catalogue import preserves optional collection identifiers, series, tags and supplied availability for future approved rows. Existing commercial fields and source image mappings are untouched.
  • Colourway text and any supplied availability are shown without inventing stock or displaying unconfirmed placeholder tokens. Product details use the same existing selection, gallery and bag callbacks.
  • The legacy SHOP click handler now accepts these registered collection destinations instead of incorrectly falling back to the general catalogue.

4. Automatic updates and configuration

src/catalogue-collections.js supplies stable collection identifiers, titles, accent colours, logo references, banner references and linked catalogue relationships. Membership is derived from the actual catalogue, not a manually maintained product-ID list. A regression test appends a future approved record and confirms it appears in the assigned collection with the original price and availability preserved.

This site uses the existing compiled master-catalogue workflow. Approved source updates appear after its normal rebuild/re-publish; no new live database, CMS or instant production-update API is claimed. Optional Collection IDs / collectionIds provide explicit stable assignments. Legacy name-based matches remain a compatibility path, not a newly invented assignment system.

src/collection-image-config.js is the single organised banner/logo image configuration. Upload an approved public asset through the existing asset workflow, set the appropriate collection's path and rebuild. Null banner paths resolve to approved catalogue photography, then named black/gold placeholders. Null logo paths never create a new mark or a new collection-to-logo mapping.
